# Backend implementation notes

`eink_frame.main:app` loads `DATABASE_URL` only if set, uses `EINK_ARTIFACT_ROOT` for local immutable artifacts, optional `EINK_FRONTEND_DIST` for built UI and distinct worker/device bearer tokens. The worker API uses a leased durable-job protocol (`src/eink_frame/jobs.py`); PostgreSQL claim uses `FOR UPDATE SKIP LOCKED`. Local render worker shares the DB and artifact root; GPU generation worker does not need direct DB access. Run `alembic upgrade head` on the designated database before scheduler/render-worker starts. Tests marked `postgresql_live` mutate their target database and are skipped unless `DATABASE_URL` is set — use only an isolated disposable test database.

This is a one-frame V4 pipeline; scene catalog is Taganrog-specific by default and location can be overridden through `EINK_LOCATION_*` and `EINK_TIMEZONE`. Neither output visual semantics nor access for UI/operator routes is validated by user authentication. `POST /api/v1/conversions` handles manual uploads, `POST /api/v1/conversions/{source_frame_id}` reprocesses saved originals, and `POST /api/v1/frames/{frame_id}/publish` changes the current frame (DB required). Draft endpoints provide preview revisions before publish; `/api/v1/generations` supplies scheduled history. See `deploy/README.md` for deployment instructions and `README.md` for complete limitations. Redis, Kafka, cloud object storage, automatic reconciler/quotas and signed OTA are not part of the asserted implementation.
