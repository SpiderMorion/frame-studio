# Architecture of the V4 baseline

FastAPI application `src/eink_frame/main.py` owns operator, device and worker HTTP APIs. PostgreSQL (SQLAlchemy/Alembic) stores schedules, generation runs, jobs, presets, device/current frame and asset metadata; immutable assets live under `EINK_ARTIFACT_ROOT`. Without `DATABASE_URL`, manual conversion and draft previews remain possible, but schedule/device/persistence endpoints respond 503. Built React frontend is served via `EINK_FRONTEND_DIST`; the backend performs normative processing. History/reprocessing use immutable original `source.png` and new frame IDs; republishing changes the current frame reference rather than modifying an earlier frame.

`scheduler_service.py` obtains Open-Meteo weather, stores snapshots and enqueues generation jobs. `spark_worker.py` claims only generation jobs over bearer-authenticated worker endpoints; `home_render_service.py` claims render jobs locally with direct DB/filesystem access and publishes current frame. The ESP32-S3 polls private HTTP device APIs, checks manifest and frame integrity, stages on SD, refreshes and acknowledges status. Worker/device tokens are not operator auth. Full pipeline needs PostgreSQL, a GPU ComfyUI instance/weights, two worker processes and reachable private networking; a single-frame manual upload does not need GPU. OTA is not implemented.

Contracts in `contracts/` define versioned manifests and provider configuration; provider catalog in `providers.py` lists planned integrations but only ComfyUI is implemented. V4 twilight is fixed 60 minutes, no Astral code. No semantic image validation guarantees correct night skies. Native panel mapping was historically checked, not revalidated for every board. Driver provenance and MIT scope are described in `THIRD_PARTY_NOTICES.md`; this source tree is not itself a running deployment. See `README.md` and `deploy/README.md` for commands, security and recovery.
