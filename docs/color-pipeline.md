# Color pipeline (V4 baseline)

`src/eink_frame/converter.py` defines nominal RGB colors black/white/yellow/red/blue/green and the supported algorithms: nearest, Floyd–Steinberg, Good Display tool-equivalent byte-clamped Floyd, Atkinson, Sierra Lite, Jarvis–Judice–Ninke, Bayer 4×4 and 8×8. Processing uses Pillow `ImageOps.fit(source.convert('RGB'), (1600,1200))`, brightness/contrast/saturation/gamma/sharpness, NumPy/Numba quantization, and a preview from logical palette indices. The code does **not** implement the previously proposed full EXIF/ICC/alpha pipeline or guarantee colorimetric accuracy on every panel. Preview is nominal, not a photograph or measurement of rendered e-ink.

For the verified panel profile the native raster is 1200×1600. `pack_vendor_rows` packs two pixels per byte (first high nibble), reverses byte-pair order *within each native row*, and produces exactly 960000 bytes. `EINK_PANEL_ROTATION=transverse` was the historically verified orientation; application default is clockwise, so explicitly configure. `GOOD_DISPLAY_FLOYD_V1` quantizes landscape first then transposes indices; other modes quantize the transformed raster. Source/preview/frame/manifest provenance and settings are kept by backend paths; no semantic image-level guard rejects implausible night skies.

The project-developed converter is included. Matching a vendor tool's output does not by itself prove copied source or grant access to the vendor's software. The separately included panel driver's vendor-derived command sequences have unresolved redistribution terms; consult `THIRD_PARTY_NOTICES.md` before downstream redistribution. Software conversion tests are not physical colorimetric certification.
